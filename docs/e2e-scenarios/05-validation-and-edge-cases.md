## 1. 개요

-   **시나리오 ID:** `TC-005`
-   **테스트 케이스:** 애플리케이션의 견고성을 확인하기 위해 다양한 예외 상황과 경계 조건을 테스트합니다.
-   **사전 조건:** 테스트는 깨끗한 상태(메모가 없는 상태)에서 시작하거나, 특정 조건에 맞는 데이터가 준비되어야 합니다.

## 2. 테스트 케이스

### 2.1. 필수 필드 유효성 검사

1.  **When** '새 메모' 폼을 열고, **제목**은 비워둔 채 내용만 입력 후 `저장하기`를 클릭한다.
2.  **Then** '제목과 내용을 모두 입력해주세요.' 라는 경고창(alert)이 나타나고, 폼은 닫히지 않아야 한다.
3.  **When** 제목은 입력하고, **내용**은 비워둔 채 `저장하기`를 클릭한다.
4.  **Then** 동일한 경고창이 나타나고, 폼은 닫히지 않아야 한다.

### 2.2. 중복 태그 입력 방지

1.  **When** '새 메모' 폼을 열고, 태그 입력창에 `중복태그`를 입력하여 추가한다.
2.  **Then** `#중복태그`가 태그 목록에 표시된다.
3.  **When** 다시 태그 입력창에 `중복태그`를 입력하고 추가하려고 시도한다 (Enter 또는 추가 버튼 클릭).
4.  **Then** 태그 목록에는 여전히 `#중복태그`가 하나만 존재해야 하며, 중복으로 추가되지 않아야 한다.

### 2.3. 빈 값/공백 문자 처리

1.  **When** '새 메모' 폼의 제목에 공백 문자(`   `)만 입력하고 저장하려고 시도한다.
2.  **Then** 필수 필드 유효성 검사에 걸려 경고창이 나타나야 한다.
3.  **When** 태그 입력창에 공백 문자만 입력하고 추가하려고 시도한다.
4.  **Then** 아무런 태그도 추가되지 않아야 한다.

### 2.4. 검색 결과가 없는 경우

1.  **Given** 메모 목록에 데이터가 있는 상태에서
2.  **When** 검색창에 절대로 존재하지 않을 것 같은 문자열(예: `!@#$RANDOM_STRING$#@!`)을 입력한다.
3.  **Then** 메모 목록 영역에 '검색 결과가 없습니다' 라는 메시지와 함께 '다른 검색어나 카테고리를 시도해보세요.' 라는 안내 문구가 표시되어야 한다.

### 2.5. 메모가 하나도 없는 경우

1.  **Given** 데이터베이스에 메모가 하나도 없는 상태로 페이지에 접속한다.
2.  **Then** 메모 목록 영역에 '아직 메모가 없습니다' 라는 메시지와 함께 '첫 번째 메모를 작성해보세요!' 라는 안내 문구가 표시되어야 한다.
